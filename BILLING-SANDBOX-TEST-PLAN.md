# WyCut Flutterwave v4 billing sandbox checklist

## Price book (fixed reference rate ₦1,400 / USD)

| Product | USD base | NGN base | 2% fee | NGN checkout total | Credits |
|---|---:|---:|---:|---:|---:|
| Single recap | $1.99 | ₦2,786 | ₦56 | ₦2,842 | 1 |
| 10-recap pack | $14.99 | ₦20,986 | ₦420 | ₦21,406 | 10 |

## Required deployment configuration

- `FLW_SECRET_KEY`: sandbox secret key first; never expose it with a `NEXT_PUBLIC_` prefix.
- `FLW_V4_API_BASE`: base URL for the exact Flutterwave v4 product enabled for the merchant.
- `FLW_V4_CHARGES_PATH`: exact direct-charge path, default `/charges`.
- `FLW_V4_CARD_FIELD`: exact encrypted-card field accepted by that v4 endpoint, default `card` (alternate supported setting: `card_encrypted`).
- `FLW_V4_VALIDATE_PATH_TEMPLATE`: exact continuation path, with `{id}` replaced by the provider charge ID and optionally `{tx_ref}` by the WyCut order reference.
- `FLW_V4_VERIFY_URL_TEMPLATE`: exact HTTPS transaction-verification URL template, with `{id}` and/or `{tx_ref}` placeholders supported by the provider endpoint.
- `FLW_WEBHOOK_SECRET_HASH`: configured webhook signing secret/hash.
- `NEXT_PUBLIC_FLW_CARD_RSA_PUBLIC_KEY`: PEM/SPKI public key only if RSA-OAEP/SHA-256 matches the enabled Flutterwave v4 card-encryption contract.
- `GOOGLE_WEB_CLIENT_ID` and `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID`: the same OAuth web client ID used by Google sign-in.
- `FIREBASE_SERVICE_ACCOUNT_JSON_BASE64`: Firebase Admin service-account JSON encoded as base64.

## Sandbox acceptance checklist

1. Confirm the encryption algorithm, public-key format, payload JSON fields, charge request field name, PIN handling, OTP continuation endpoint/body, verification endpoint, and webhook signature against the merchant's actual v4 docs.
2. Sign in with Google, buy one recap, complete a successful sandbox card charge, and confirm one credit is added to `wycut_users/{google-sub}`.
3. Repeat with the 10-recap pack and confirm exactly ten credits are added.
4. Exercise the bank PIN challenge and OTP challenge independently; incorrect codes must not grant credits.
5. Send the same successful webhook twice; the second event must be idempotent and must not add credits twice.
6. Send a forged webhook, wrong amount, wrong currency, wrong transaction reference, wrong provider ID, and a transaction for a different Google account; all must be rejected without granting credits.
7. Simulate provider timeout, then use `/api/billing/status` to confirm the existing order before attempting another payment.
8. Generate a script with one credit; confirm one credit is reserved. Simulate script-provider failure and confirm it is refunded. Confirm no-credit users receive HTTP 402.
9. Confirm narration calls are accepted only for a recap generated by that same Google account and that the per-recap request limit is enforced.
10. Test the checkout and script flow on a real Android APK and on web before enabling live credentials.

**Do not use live card data during development. Do not enable live charging until all checks pass.** The current project provides the flow and configurable integration points, but a sandbox result is required to certify the exact merchant-specific v4 protocol.
